# QR Code 點名與加分系統

**正式網址**

| 用途 | 網址 |
| --- | --- |
| 學生簽到頁 | <https://qr-attendance-pied.vercel.app/> |
| 教師 QR 產生器 | <https://qr-attendance-pied.vercel.app/qr> |
| 原始碼 | <https://github.com/Gary0302/qr-attendance> |

推到 GitHub `main` 會自動重新部署。

用一張投影在螢幕上的 QR Code，讓全班同學用自己的手機完成點名與加分登記，
資料直接寫進 Google 試算表。實作依據 [`spec.md`](spec.md)。

```
學生手機  ──掃 QR──▶  前端網頁 (Vercel / GitHub Pages)
                          │  POST JSON
                          ▼
                    Google Apps Script Web App
                          │  讀寫
                          ▼
                     Google 試算表（名冊 / 紀錄）
```

## 檔案

| 檔案 | 用途 |
| --- | --- |
| `index.html` | 學生簽到頁（只輸入學號），以 `?mode=` 切換模式 |
| `qr.html` | 教師用 QR Code 產生器，附全螢幕投影模式 |
| `config.js` | **唯一需要修改的設定檔**（API 網址、課程名稱） |
| `apps-script/Code.gs` | 後端 API，貼到 Apps Script 編輯器 |
| `vercel.json` | Vercel 靜態託管設定 |

## 試算表選單

貼上 `Code.gs` 並重新整理試算表後，上方會多一個「**點名系統**」選單：

| 項目 | 用途 |
| --- | --- |
| ① 初始化工作表 | 建立標題列、凍結首列、設定欄位格式 |
| ② 設定輪替密語 | 跳出視窗輸入，防止 QR 被截圖轉傳 |
| 停用輪替密語 | 改回固定網址 |
| 清除場次／裝置紀錄 | 想重複使用同一個場次代碼時執行；不影響分數與出席時間 |
| 系統狀態 | 顯示程式版本、名冊人數、各項防護是否啟用 |

選單是編輯器端的功能，**改完存檔重新整理試算表就生效，不需要重新部署**
（網頁應用程式讀的是指令碼屬性，密語設定即時生效）。

## 安裝步驟

### 1. 建立試算表與後端

1. 新建一份 Google 試算表，命名隨意。
2. 上方選單 **擴充功能 → Apps Script**。
3. 把 `apps-script/Code.gs` 的內容整份貼進 `Code.gs`，覆蓋原本的範例程式。
4. 存檔後，在編輯器上方函式選單選 **`setupSheets`** 並按執行，
   第一次會跳出授權視窗，同意即可。執行完試算表會多出「名冊」與「紀錄」兩張工作表。
5. 右上角 **部署 → 新增部署作業 → 類型選「網頁應用程式」**：
   - 執行身分：**我**
   - 誰可以存取：**所有人**（必須選這個，學生才不用登入 Google）
6. 複製取得的網址（結尾是 `/exec`）。

> 之後每次修改 `Code.gs`，都要重新 **部署 → 管理部署作業 → 編輯 → 版本選「新版本」**，
> 否則線上跑的還是舊程式。

### 2. 匯入學生名單

專案內的 `name.txt`（學務系統匯出的名單）會被轉成 `roster.csv`：

```bash
python3 tools/make-roster.py     # name.txt → roster.csv
```

在 Google 試算表：**檔案 → 匯入 → 上傳 → 選 roster.csv**，
匯入位置選「**取代目前工作表**」，分隔符號選「逗號」。
匯入後回到 Apps Script 執行一次 `setupSheets()`，補上格式與凍結首列。

> `name.txt` 與 `roster.csv` 含學生姓名與電子信箱，已被 `.gitignore` 與 `.vercelignore`
> 排除，不會進版控、也不會部署到公開網站。**請勿手動加回去。**

### 3. 設定前端

編輯 `config.js`：

```js
window.APP_CONFIG = {
  API_URL: 'https://script.google.com/macros/s/AKfycb...../exec',
  SITE_URL: '',            // 部署後填正式網址，或留空自動偵測
  COURSE_NAME: '資訊概論 星期三第三節',
};
```

### 4. 部署前端

這是純靜態網站，沒有建置步驟。

已部署在 Vercel 並連上 GitHub repo，`git push` 到 `main` 就會自動上線。
要手動部署：`vercel deploy --prod --yes`

注意 `vercel.json` 開了 `cleanUrls`，所以教師頁的網址是 `/qr` 而不是 `/qr.html`。
`apps-script/`、`spec.md`、`README.md` 已由 `.vercelignore` 排除，不會被部署。

### 5. 產生 QR Code

打開 `https://你的網址/qr.html`，選模式 → 按「投影全螢幕」→ 投影給全班掃。

## 學生只需要輸入學號

學生端只有一個欄位：**學號**。姓名一律從名冊查，理由是：

- 少打一個欄位，全班簽到更快
- 學生打錯字、打綽號、用全形空白都不會弄髒名冊
- 簽到成功後畫面會顯示名冊上的姓名（「楊喬宇，已記錄簽到時間…」），學生自己就能確認有沒有打錯學號

學號不在名單上會直接擋下並顯示是哪個學號，不會建立空白姓名的資料列。

### 學號輸入的容錯

手機上打學號會出現各種狀況，前後端用同一套 `normalizeId()` 收乾淨：

| 學生打的 | 系統收到 |
| --- | --- |
| `b147610001` | `B147610001` |
| `  B147610001  ` | `B147610001` |
| `B-147-610-001` | `B147610001` |
| `Ｂ１４７６１０００１`（全形） | `B147610001` |
| `B　147610001`（全形空白） | `B147610001` |
| `b147610001@student.nsysu.edu.tw` | `B147610001` |

輸入框會邊打邊清乾淨，同時保住游標位置（不然刪字會亂跳）。

查不到學號時，後端會找「幾乎確定是打錯」的候選並提示：

- **形近字**：`B14761OOO3`（數字 0 打成英文 O）→ 提示 `B147610003`
- **漏打開頭字母**：`147610006` → 提示 `B147610006`

畫面會出現「改用 B147610003 送出」的按鈕，**但不會自動套用** —— 簽到成別人比多按一下糟得多。
只有這兩種情況會提示；一般的打錯數字不會提示，避免猜成另一個真實同學的學號。

## 三種模式

| 網址 | 行為 |
| --- | --- |
| `?mode=attendance` | 寫入 C 欄「出席時間」為伺服器當下時間 |
| `?mode=classBonus` | D 欄「課堂加分」累加 |
| `?mode=lectureBonus` | E 欄「講座加分」累加 |

沒帶 `mode` 參數時預設為 `attendance`。

### 選用參數

| 參數 | 說明 |
| --- | --- |
| `session` | 場次代碼，例如 `session=0911-3`。帶了就會擋掉同一人在同一場次的重複加分。 |
| `points` | 這次加幾分，預設 1，後端上限 10（防止有人改網址狂加分）。 |
| `token` | 固定通行碼，需與 `Code.gs` 的 `CONFIG.TOKEN` 相同。 |
| `s` / `c` | 輪替式 QR 的時間格與簽章碼，由 `/qr` 自動產生，不要手動填。 |

範例：`https://你的網址/?mode=classBonus&session=0911-3&points=2`

## 資料表欄位

「名冊」工作表共 9 欄：A~F 直接來自學務系統名單，G~I 由本系統寫入。

| 欄 | 名稱 | 來源 | 說明 |
| --- | --- | --- | --- |
| A | 序號 | 名單 | |
| B | 學號 | 名單 | **查詢鍵**，文字格式，開頭的 0 不會被吃掉 |
| C | 姓名 | 名單 | 以名冊為準，學生打錯不會覆寫 |
| D | 年級 | 名單 | |
| E | 電子信箱 | 名單 | |
| F | 選上否 | 名單 | 自動新增的非名單學生會標記「未在名單」 |
| G | 出席時間 | 系統 | 真正的日期值，顯示格式 `YYYY-MM-DD HH:mm:ss` |
| H | 課堂加分 | 系統 | 整數，累加 |
| I | 講座加分 | 系統 | 整數，累加 |

「紀錄」工作表逐筆記下每次送出（時間、模式、學號、送出的姓名、名冊上的姓名、場次、分數、結果）。
學生輸入的姓名和名冊不同時會標記「姓名不符」，方便事後核對代簽或打錯字。

### 只允許名單上的學生簽到

`Code.gs` 的 `CONFIG.ROSTER_ONLY` 預設為 `false`（不在名單者自動新增並標記）。
改成 `true` 之後，查無學號會直接擋下，適合不想讓旁聽生混入的情況。

## 同時大量簽到

全班同時掃碼時，數十個請求會同時想寫同一份試算表。

**不會掉分。** 後端用 `LockService` 把請求排隊，一次只有一個在讀寫。
沒有鎖的話，兩個學生可能同時讀到「目前 3 分」，然後都寫 4 分，其中一筆就消失了。

**不會重複計分。** 每次送出都帶一個 `nonce`，同一筆簽到（模式＋學號＋場次）在 3 分鐘內
沿用同一組。學生等太久重按送出，後端認得就直接回上次的結果，不會再加一次分。

**逾時時間是對齊的。** 後端等鎖最多 25 秒，前端等 45 秒 —— 前端一定等得比後端久，
所以學生看到的一定是後端給的明確訊息（「同時簽到的人太多，請等 10 秒再送出」），
而不是「不知道到底成功沒有」的逾時。

**效能。** 每個請求打 3 次試算表 API（查學號、寫值、寫紀錄），約 1 秒。
33 人最壞情況循序處理約 30 秒，但實際上學生掃碼會分散在一兩分鐘內，不會全部擠在同一瞬間。
Apps Script 的同時執行上限是 30 個，超過會排隊。

## 防止 QR Code 被轉傳

預設的固定網址有個大洞：學生截圖傳給沒來的同學，對方在家也能簽到。
啟用**輪替式 QR** 之後，QR 每 30 秒換一次，過期的碼後端直接拒絕。

### 啟用方式

1. 打開試算表 → 上方選單 **點名系統 → ② 設定輪替密語** → 在跳出的視窗輸入密語。

   Apps Script 的「執行」按鈕不能帶參數，所以用選單的對話框輸入。
   密語存在**指令碼屬性**，不會留在 `Code.gs` 原始碼裡（這個 repo 是公開的）。

   > 看不到「點名系統」選單？貼上新的 `Code.gs` 存檔後，把試算表**重新整理**一次。

2. 打開 `/qr`，在「輪替密語」欄輸入**同一串密語**。
   密語只存在你這台電腦的瀏覽器（localStorage），不會進 QR、不會上傳、學生看不到。

3. QR 下方會出現倒數條，投影全螢幕時學生也看得到。

停用：選單 **點名系統 → 停用輪替密語**，並清空 `/qr` 的密語欄。

### 原理

教師端每 30 秒重算一次：

```
slot = floor(現在秒數 / 30)
code = HMAC-SHA256(密語, "mode|session|slot") 取前 10 個 hex 字元
網址 = .../?mode=...&session=...&s=<slot>&c=<code>
```

後端用同一把密語重算並比對，同時確認 `slot` 與伺服器時間相差不超過 ±1 格。
因為簽章綁定了 `mode` 和 `session`，拿點名的碼去換加分、或拿上禮拜的碼來用，都會被擋。

實測擋下的情況：過期碼（180 秒前）、亂猜的碼、完全不帶碼、竄改 mode、竄改 session、
偏移超過 ±1 格。誤差 ±1 格是留給學生「掃碼後打字」的時間，實際有效約 30～90 秒。

### 一機一人

`CONFIG.MAX_STUDENTS_PER_DEVICE`（預設 `1`）擋另一個洞：學生用自己的手機連續幫好幾個朋友簽到。
每支手機第一次進來會拿到一組隨機裝置代碼存在 localStorage，同一場次只能登記一個學號。

改成 `0` 可以關掉這個限制。有學生手機沒電要借同學的手機時，需要你手動處理。

### 誠實說明：這擋得住什麼、擋不住什麼

**擋得住**：課後把截圖丟群組、上禮拜的 QR、自己猜碼、竄改網址參數、
一支手機幫全組簽到（不清資料的話）。

**擋不住**：

- **即時轉傳**。學生視訊把螢幕轉給在家的同學，對方 30 秒內完成簽到就會過。
  要壓縮這個空窗，把 `ROTATE_PERIOD_SEC` 調到 15 秒，但學生打字會比較趕。
- **清掉瀏覽器資料**換新裝置代碼。一機一人是增加麻煩，不是絕對防堵。
  真正的價值是「紀錄」工作表的**裝置**欄留下軌跡，事後看得出同一支手機送過哪些學號。
- **人不在教室但有人幫他拿手機**。任何掃碼系統都解決不了這件事。

實務上建議：QR 只投影 1～2 分鐘、每堂課換 `session`、事後掃一眼紀錄表的裝置欄。

## 實作上的幾個決定

- **CORS**：Apps Script 無法回應 `OPTIONS` preflight，所以前端用
  `Content-Type: text/plain` 送 JSON 字串，讓它符合 CORS「簡單請求」的條件。
  後端 `parseRequest()` 會自行解析 body。
- **並行寫入**：全班同時掃碼會有數十個請求同時讀寫同一格。後端用
  `LockService` 序列化處理，避免兩個請求同時讀到舊分數而互相覆蓋。
- **姓名以先到者為準**：後來送出的不同姓名不會覆寫名冊，只會記在「紀錄」表，
  避免有人打錯字或惡意改掉別人的姓名。
- **時間由伺服器決定**：不採用瀏覽器時間，學生改手機時鐘沒有用。

## 已知限制

- **API 是公開的**。任何拿到網址的人都能送資料，`token` 只是速度障礙而非安全機制
  （QR Code 本身就看得到）。要嚴格防範請每堂課換 `session`，並用「紀錄」工作表事後稽核。
- **無法偵測代簽**。系統只能確認「有人用這組學號送出」，無法確認人在教室。
  輪替式 QR 與一機一人能擋掉大部分情況，細節見上面的「防止 QR Code 被轉傳」。
- **個資**：`name.txt` / `roster.csv` 含 33 位學生的姓名與電子信箱，已排除於版控與部署之外。
  若要換名單，請直接替換本機的 `name.txt` 再重跑轉檔腳本。
- `clearSessionMarks()` 可清掉所有場次去重紀錄（要重複使用同一個 session 名稱時執行）。
